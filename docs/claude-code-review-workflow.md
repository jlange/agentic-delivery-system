# Claude Code Review Workflow

This document defines how Claude Code may be used as a secondary reviewer or alternate implementation agent in client projects.

## Purpose

Claude Code is optional in this delivery system.

Use it to provide an independent review path, an alternate implementation perspective, or focused debugging support.

Codex remains the default primary agent unless a task explicitly assigns Claude Code.

## Recommended uses

Use Claude Code for:

- independent pull request review
- architecture critique
- debugging difficult failures
- test plan review
- security and edge-case review
- alternate implementation plans
- comparing tradeoffs before a large change

## Default review role

Claude Code should usually act as a reviewer, not the same agent that implemented the change.

Preferred pattern:

- Codex implements a bounded task.
- Claude Code reviews the branch or diff.
- Codex or the human applies accepted fixes.
- Final merge remains human-approved.

Alternative pattern:

- Claude Code implements a bounded task.
- Codex reviews the branch or diff.
- Final merge remains human-approved.

## Review inputs

A Claude Code review should receive:

- task ID
- requirement IDs
- approved acceptance criteria
- branch name
- files changed
- verification commands
- known risks
- what kind of review is requested

## Review output

Claude Code review should produce:

- blocking issues
- non-blocking issues
- missing tests
- security concerns
- requirement mismatches
- unclear behavior
- suggested fixes
- final recommendation

## Boundaries

Claude Code must not:

- push directly to `main`, `staging`, `qa`, or `dev`
- merge pull requests
- deploy to production
- modify billing or account settings
- access production secrets
- use production client data
- approve its own work
- exceed task scope
- continue retrying after repeated failures
- add comments or metadata claiming code was generated by an agent

## Cost controls

Use Claude Code intentionally.

Do not run redundant reviews on every small change unless the project requires it.

Use Claude Code reviews for:

- high-risk changes
- authentication
- authorization
- database migrations
- payments
- deployment workflows
- client-critical user flows
- large refactors
- unclear requirements

## Human approval required

Human approval is required before:

- authenticating paid accounts
- enabling usage-based billing
- using Claude Code on sensitive client material
- granting repository or organization permissions
- merging reviewed work
- deploying reviewed work
