# Working agreements

- Read the approved task and linked requirements before editing.
- Ask when a requirement is ambiguous; do not silently invent product behavior.
- Plan before changing multiple modules.
- Use the smallest defensible change.
- Do not edit files outside the task's allowed paths.
- Do not add a production dependency without documenting the reason.
- Never place secrets, API keys, client data, access tokens, or `.env` contents in source control.
- Run the repository verification commands before reporting completion.
- Implementation agents must not approve their own work.
- Every pull request must cite requirement IDs and include verification evidence.
- Record durable discoveries in `docs/learnings/`.
- Do not push directly to the configured integration or release branches.
- After a delivery wave is approved, continue routine engineering work through branch
  creation, verification, pull request, configured checks and reviews, authorized merge, and
  post-merge verification without asking for routine human approval.
- Pause for financial, legal, contractual, licensing, regulatory, compliance, missing
  human-only credentials or permissions, ungranted production authority, or an
  irreversible business decision not resolved by approved policy.
- Do not treat ordinary tool permission prompts as business decisions. Use the
  environment's approval mechanism for safe, in-scope operations.
- Do not deploy to production or perform destructive operations without existing
  authorization and appropriate safeguards.

## Generated-code hygiene

- Do not add comments, banners, commit messages, pull-request text, file headers, metadata, or documentation stating that code was generated by an AI, agent, assistant, or language model.
- Do not add signatures such as "Generated by Codex," "AI-generated," or similar wording.
- Do not add AI-related `Co-authored-by` trailers to commits.
- Write code, documentation, tests, and commit messages in the same professional style expected from a human development team.
- Do not remove legally required license notices, third-party attribution, copyright notices, or provenance required by the client or repository policy.
- Do not falsify authorship records or make claims about who personally wrote specific code.

## AI usage and cost controls

- Prefer the smallest capable model and the shortest sufficient context for each task.
- Do not start more than three write-capable agents concurrently.
- Do not start additional agents merely to obtain redundant opinions unless explicitly requested.
- Use read-only exploration before assigning implementation work.
- Give each agent a bounded task with explicit allowed paths, acceptance criteria, and stopping conditions.
- Do not repeatedly resend entire repositories, lengthy logs, generated artifacts, or unchanged requirements when a focused excerpt or file reference is sufficient.
- Summarize long investigation results before handing work to another agent.
- Reuse approved plans, requirement files, task files, and repository documentation rather than reconstructing context in every prompt.
- Stop after two unsuccessful implementation attempts or repeated test failures and request human review.
- Do not automatically retry rate-limit, authentication, billing, quota, or credit errors.
- Do not use premium, high-compute, fast, or extended-reasoning modes unless the task justifies them or a human approves them.
- Do not launch background, scheduled, recursive, or open-ended agent work without explicit approval.
- Do not use API credentials or usage-based billing when an authenticated included-plan workflow is available, unless explicitly approved.
- Before any potentially expensive operation, state the proposed number of agents, expected scope, model or execution mode, and stopping condition.
- Pause when a configured project budget, usage threshold, credit threshold, or task limit is reached.
- Report usage anomalies, unexpectedly large context, repeated retries, runaway subprocesses, or excessive parallelism immediately.
